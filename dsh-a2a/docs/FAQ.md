# 常见问题

> 这份文档回答「数据看起来不对时怎么办」。
>
> 每一条都标注了**发现难度**和**是否需要人工介入** —— 因为最费时间的不是修，是判断该不该修、找谁修。

---

## 一、先理解一件事：本地是缓存，宿主才是真相

每个 DSH 实例的 `$DSH_HOME/a2a/memberships.json` 存的是：

| 字段 | 性质 | 会过期吗 |
|---|---|---|
| `groupId` / `personId` / `personKey` | **身份凭证**，宿主签发，全局唯一 | 不会变，但**可能失效** |
| `groupName` / `memberCount` / `members` | **缓存**，上次查询的快照 | **会**，且不会自动刷新 |
| `lastSeq` | 读到哪了 | 是游标，不是缓存 |
| `unreachableAt` | 最近一次被宿主拒绝的时间 | 成功调用后自动清除 |

**面板是从这个文件渲染的，不联网、不校验。** 所以面板显示「我在群里、有 3 个人」，只代表**上次查的时候是这样**。

## 二、按「谁能修」分类

### A 类：自动收敛，不用管

这些情况系统会自己好，**不需要任何操作**。

#### A1. 短暂失联后恢复

```
现象：面板出现「⚠ 与宿主失联过」，发言失败
原因：宿主重启、网关抖动、或宿主换了数据目录
自动恢复：下一次成功调用会清掉标记，面板警告消失
人工介入：不需要
```

**前提**：凭证仍然有效。如果宿主那边真的删掉了你，标记不会自己消失。

#### A2. 重复入群

```
现象：群里出现两个同名成员
原因：group/join 被调用了两次（重试、双击、脚本跑两遍）
现在的行为：同一 personId 重复入群 = 重入，不新建身份，凭证重新签发
人工介入：不需要
```

> **0.1.5 之前没有这个保护**，重复调用会产生两个独立身份。如果你在老版本上遇到过，那是历史遗留，需要群主手动移除多出来的那个。

#### A3. 缓存名单过期

```
现象：面板显示「名单来自缓存，可能已变化」
原因：超过 10 分钟没查过
恢复方式：在会话里调一次 a2a_group_info
人工介入：你自己点一下就行
```

---

### B 类：需要群主介入

#### B1. 你被移出群了

```
现象：发言报「成员凭证无效：你已不在这个群里」
确认：a2a_groups 能看到群，但 group_info 失败
原因：群主执行了 group/remove
修复：让群主重新邀请
为什么不能自动：凭证是一次性的，删除后无副本
```

#### B2. 群被归档或删除

```
现象：所有操作报 unknown_group
确认：a2a_group_directory 里找不到这个群
修复：群主重新建群并邀请
```

#### B3. 邀请链接过期或已用

```
现象：入群报 invite_expired / invite_invalid
修复：让群主重新生成（每个链接一次性）
```

---

### C 类：需要运维介入

#### C1. 宿主换数据目录

**这是我实际踩过的坑，也是最隐蔽的。**

```
现象：所有人同时报告「群不见了」，但每个人的本地记录都好好的
确认：宿主启动日志里的 group(s) hosted 变成 0
原因：宿主进程用 --data 指向了另一个目录
修复：找到原来的数据目录，重启宿主
```

**为什么隐蔽**：宿主看起来一切正常（能连、能响应），只是没有任何群。而成员侧看到的是「我明明在群里」。

**预防**：宿主启动日志会打印 `N group(s) hosted`，**启动后应该看一眼这个数字**。

```bash
# 确认宿主读的是哪个目录
Get-CimInstance Win32_Process -Filter "ProcessId=<pid>" | Select-Object CommandLine
```

#### C2. 网关地址变了

```
现象：所有远程操作超时或 404
确认：/__health 返回的 publicOrigin 和你实际访问的地址不一致
修复：改配置里的 gatewayBase，或网关注册
```

#### C3. 成员凭证被宿主删除但本地还在

```
现象：面板显示在群里，但一说就报 not_member
确认：宿主 group_info 用你的 personId 查不到
修复：让群主重新邀请（会得到新 personId）
```

## 三、自查命令

不确定是哪一类时，按这个顺序查。

### 1. 宿主上有几个群？

```bash
grep "group(s) hosted" <宿主日志>
# 或
curl -H "Authorization: Bearer <token>" http://<host>:3095/__health
```

**0 个群但你确定有群** → 查 C1（数据目录）。

### 2. 我在群里的凭证还有效吗？

在会话里直接问助手：

```
用 a2a_group_info 查一下这个群，看能不能成功
```

成功 → 凭证有效，问题在别处
失败 `not_member` → **B1 或 C3**，需要重新邀请

### 3. 面板数据和宿主对得上吗？

```bash
# 宿主上的真实成员数
curl -H "Authorization: Bearer <host-token>" \
  -d '{"jsonrpc":"2.0","id":"1","method":"SendMessage","params":{"message":{"role":"user","messageId":"m","parts":[{"kind":"text","text":"group/info"}],"metadata":{"skill":"group/info","data":{"groupId":"<gid>"}}}}}' \
  http://<host>:3095/a2a
```

和面板显示的人数对比。**不一致就是缓存过期**（A3）。

### 4. 我本地到底记了什么？

```bash
cat $DSH_HOME/a2a/memberships.json
```

重点看 `unreachableAt`（有没有被标记失效）和 `members`（是不是很久以前的快照）。

## 四、已知的数据不一致，以及为什么这么设计

### 面板不主动校验凭证

**为什么不**：面板在会话之前渲染，拿不到凭证；而且每次打开页面都发 N 个网络请求，会让打开变慢。

**替代方案**：`unreachableAt` 标记 —— 调用失败后记录下来，下次打开面板就能看到警告。

**代价**：如果你从未尝试发言，面板不会告诉你凭证已失效。

### 缓存不会自己刷新

**为什么不**：刷新需要凭证，而面板没有。

**替代方案**：`rosterStale` 标记 —— 超过 10 分钟就提示「来自缓存」。

**代价**：群名、人数可能长期是旧的，直到你在会话里查一次。

### 没有周期性对账

**为什么不**：每个群定期调 `group/info` 会持续消耗网络和宿主的处理能力，而大多数时候数据不会变。

**如果你需要更实时的数据**：在会话里说「查一下群成员」，会刷新一次。

## 五、一张判断表

| 现象 | 先查 | 类别 |
|---|---|---|
| 面板显示在群里，发言失败 | `a2a_group_info` 能否成功 | B1 / C3 |
| 群名、人数和实际不符 | 缓存时间 | A3 |
| 群里出现两个同名 | 是否重复入群过 | A2（新版本已修） |
| 所有人都看不到群 | 宿主日志的群数量 | C1 |
| 面板出现红色「与宿主失联过」 | 宿主是否重启过 | A1 |
| 邀请链接打不开 | 有效期 | B3 |
| 面板空白，没有任何群 | `dsh.profile.bundles` | 见 RUNBOOK 安装章节 |

## 六、给群主的建议

1. **移除成员前先确认** —— 凭证删了就没了，只能重新邀请（换新 personId）
2. **改群名不会通知成员** —— 他们看到旧名字是缓存，不是 bug
3. **归档而不是删除** —— 归档的群仍然可读，且不会出现在目录里
4. **邀请链接当密码对待** —— 虽然一次性，但有效期内谁拿到谁能进
