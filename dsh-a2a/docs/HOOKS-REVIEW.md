# HOOK 设计评审结论清单

> 状态：评审进行中，持续更新
> 作用：把群里散落的评审结论沉淀成结构化清单，避免「评审过了」只剩口头。
> 格式：`约束 / 理由 / 怎么验证 / 谁提的 / 等级 / 状态`

**等级约定**（石磊 #117）：
- **E1** 实测（跑过、带可复现命令+输出）
- **E2** 源码可见（对着原文核）
- **E3** 推理（只看摘要/常识，未看实现）

**类别约定**（石磊 #112）：
- **A** 数据形状/语义 —— 必须现在定（改了要重算验收基线）
- **B** 实现手段 —— 留实现阶段，但写成约束
- **C** 验收用例 —— 必须现在产出（是设计缺陷的探针）

## 评审纪律（石磊 #112 提出，已采纳）

1. 每条约束必须带「怎么验证」，说不出验证方式的不是约束是愿望。
2. 等级标 E1/E2/E3，E1 必须带可复现命令+输出。
3. A/C 类现在定，B 类留实现阶段但写成约束。
4. 否决的设计留在文档里带否决理由，不静默删除。
