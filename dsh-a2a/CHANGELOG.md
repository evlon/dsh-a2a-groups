## [0.1.38] — 2026-11-07

> setup 页面区分 CLI 与桌面版；面板传输错误不再直出 405；CI 的 provenance 降级为可选。

### 修复

- **`/setup` 安装指引区分终端 CLI 与桌面版**：原来只有 `dsh plugin --profile web add ...`。桌面版跑的是 `profiles/desktop` 且用它自带的 dsh，照做会装进 web profile —— 表现是「面板能打开，一刷新就报 HTTP 405」。现在先分流，桌面版分支含一段自动定位脚本（进程路径 → 注册表卸载项 → 校验文件存在；校验那步必要，因为机器上可能同时装着两个同名产品），并说明装完要**完全退出应用**。
- **面板错误文案**：`transport failure for /a2a-panel/confirm-settings: HTTP 405` 直出给了用户，暴露内部路由且不给任何可执行信息。新增翻译：405 → 指向「插件装进了另一个 profile」，401 → 鉴权；未识别的错误原样透传（给未知故障编好话会把唯一可诊断的细节埋掉）。
- **RUNBOOK §3.1** 拆成 CLI / 桌面版 / 两个源三节，桌面版给出定位脚本与验收判据（`/a2a-panel/ping` 从 405 变 401）。

### 构建

- **CI 的 `--provenance` 改为「尽力而为」**：2026-11-07 sigstore 的 Rekor 连续 40 分钟返回 500，`--provenance` 会把它变成硬发布失败——包已构建好、测试全过，却因为第三方服务故障发不出去。现在先试带签名，检测到 `TLOG_CREATE_ENTRY_ERROR` 才降级重发，并在 step summary 与 `::warning::` 里注明「本次无签名证明」。其它失败照旧不重试。

### 版本说明

- **0.1.37 未发布**：同样的 sigstore 故障，tag `v0.1.37` 已推但 npm 上没有该版本，其内容全部包含在 0.1.38 里。跳号（如 0.1.26 / 0.1.28 / 0.1.29 / 0.1.32）此前也发生过。

## [0.1.24] — 2026-11-07

> 面板「协作群」三个易用性补全 + 两个 `/setup` 修复。

### 新功能

- **「新建一个群」按钮**：未加入面板新增「④ 新建一个群」，点击把 `a2a_group_create` 指令填进输入框（群名/主题留空待改）。此前未加入面板只有「重新加入 / 邀请链接 / 自己找群」，没有「开一个群」的入口。
- **「设置」标签页（表单版）**：协作群面板新增「设置」tab，展示当前实例的接入配置为**表单**（网关地址 / 网关里的名字 / 网关密钥三项核心字段 + 「高级」折叠的对外地址 / 令牌），带中文标签、预填当前值、逐个校验。保存走 DSH 官方 `configEditor` 服务（原子写 + 校验 + 失败回滚 + 热加载），新手不用懂 YAML 缩进、不用找 cordis.patch.yml。

### 修复

- **`/setup` 配置说明去掉多余的 `server` 段**：加入协作群只需 `groups` + `client` + `tools` + `promptSection`；`server` 段是「把自己开放给同事点对点调用」的进阶能力（默认关），原来塞进核心配置说明给新人两个坑（token 占位、publicUrl 占位）。改为页面底部「进阶」小节单独说明。
- **`/setup` 配置说明补上「安装插件」步骤**：原指令漏了最前置的 `dsh plugin --profile web add dsh-a2a-groups@latest`，没装包时 cordis.patch.yml 里的 name 解析不到。改为三步（安装 → 挂载 → 配置）。
- **「重新加入」按钮文案修正**：原文案断言「我本机已经有身份，不需要邀请链接」——这只在本实例账本里已有该群凭证时才成立，新实例没有凭证仍需邀请链接。改为明确两个分支。

## [0.1.23] — 2026-11-06

> 新功能 + 一轮黑盒测试修复 + ownerless 收口 + 死代码清理。

### 新功能

- **长轮询 `a2a_group_wait`**（DSH 与 MCP 共用同一份 spec）：阻塞最多 `timeoutMs`，有新消息立刻返回（`hasNew:true` + 增量），窗口内无消息则返回 `hasNew:false`（非错误）。这是 MCP 客户端「无推送」下的官方常驻监听用法：后台循环调它，有消息即报、超时静默续轮。
- **宿主新增 `group/wait` skill**：复用现成的 `store.subscribe` watcher registry——`post`/`appendSystem` 每次本就 `notify()`，长轮询直接挂在这个通知上，无新造状态。订阅后立即补读一次，堵住「先读后订阅」之间的丢消息窗口。
- **`/setup` 常驻入口**（dev2 协作）：`http://<宿主>/setup` 是固定的、可收藏的「只接入协作」配置页，直接 200 不重定向、不铸一次性 token。
- **保存名片后立即刷新**：面板写昵称/个人介绍成功后，立刻 `group/info` 读回写进本地 ledger，UI 不再需要整页刷新才看到变化；轮询同时返回 cards。
- **`a2a_self_check` 引导**：检测到无推送环境时，提示用 `a2a_group_wait` 循环实现准实时收消息。

### 修复（同事黑盒测试反馈，12 条）

按严重度逐条核实，9 条已修、1 条设计权衡、2 条关闭：

- **approvals/decide 对网关托管群报 `not_hosted_here`** → 改走宿主 `group/requests`/`group/decide` 技能，群主可经 MCP 审批入群。
- **leave 首次必 retry、二次才成功** → 根因是 standalone 宿主 identities stub 缺 `remove` 方法，`group/leave` 共享体抛 TypeError（store 已删成员，重试才因 not_member 走成功）。补 no-op remove。
- **personId 全程不暴露** → `a2a_group_summary` 成员行补 personId，`person_send`/`group_kick` 正路径可用。
- **唯一群主 leave 后无主** → join 检测 ownerless 提拔首个加入者为群主（见下「ownerless 收口」）。
- **已是成员仍可 request** → `requestJoin` 加 `already_member` 拒绝 + 新错误码。
- **person_inbox 不返回 dmId** → render 补 dmId，`person_ack` 可正常调用。
- **wait 省略 sinceSeq 重放历史** → 默认用成员已读 lastSeq。
- **timeoutMs 非法值静默钳到 1s** → 显式非法值抛 `bad_argument`。
- **名片/昵称显示长串 session id** → join 兜底从 session id 改为短默认「成员」；`set_card` 完整支持 displayName 写入并同步 person 表；同事名片从「本地陈旧 person 表」改为「聚合各群 roster」。

### 设计权衡（保留）

- unlisted 群 `request` 报「找不到这个群」是**有意的安全措辞**（不承认 unlisted 群存在），不改。

### ownerless 收口（同事拍板方案 A）

- 最后一人 leave **拒绝**（`last_member` 错误码），提示「先转让群主或归档」，从源头堵掉无主群。
- 保留 join 时 ownerless 提拔兜底（救存量脏数据：悬空 owner 指针 + role 降级）。

### 重构

- **删死代码**：`hashPassword`/`verifyPassword`/`SCRYPT_*`/`bad_password`/`randomPassword`（「无群密码」重构后遗留，运行时零引用）。
- **清理过时命名**：probe 脚本默认 agent `dsh-group`/`dsh-groups` → `agent-group-host`；resources.yaml 删单群通配符、key_hash 补真实值使 smoke 开箱即用。
- **验证证据目录规范化**：test-report → verification/（报告进 git），截图归 .shots/（gitignore）。
- **根目录清理**：删一次性探针脚本与过时 PLAN.md。

### 关键约束

- `timeoutMs` 被宿主夹在 1–55 秒（保在 MCP 客户端工具调用超时之内）；**常驻监听建议 ≤30s**（客户端工具超时约 30s，设 55s 会被 -32001 掐断）。
- `bridge.send` 的 HTTP 超时取 `waitMs + 5000`，否则 HTTP 层会先于宿主的诚实「无消息」返回。
- 端到端实测（经网关真实往返）：8 秒窗口 1 秒后 post → **1.3 秒返回**；3 秒窗口无 post → **3.0 秒返回 `hasNew:false`**。

## [0.1.10] — 2026-11-06

> 新功能：**人工确认**。收到同事的消息时，可以先让你本人确认再开始处理。
> 全部是设置项，每个会话可以有自己的选择。

### 新功能：人工确认

**为什么需要**：同事能决定自己什么时候回、回什么质量；发起者不能强制。真实的协作是这样，插件里也该这样。
所以收到别人的任务时，这个会话可以先停下来问你。

**怎么开启**：群成员面板底部 → 人工确认 → 关掉「沿用全局设置」，勾选「启用人工确认」。
也可以直接在 profile 的 `groups.humanConfirm` 里改默认值。

**五项设置，每项都能调**

| 设置 | 选项 | 默认 | 说明 |
|---|---|---|---|
| 启用人工确认 | 开/关 | 关 | 总开关 |
| 什么时候问 | 被 @ 时 / 每条消息 / 从不 | 被 @ 时 | 只有 @ 到你的消息才值得打断 |
| 确认方式 | 界面提问 / 即时通讯消息 | 界面提问 | 后者**未实现**，选中会明确报错 |
| 没人回答时 | 拒绝执行 / 仍然执行 / 一直等下去 | 拒绝执行 | 见下 |
| 等待时长 | 秒 | 300 | 只在「拒绝/仍然执行」时有效 |

**为什么默认「拒绝执行」**

- `一直等下去`：你不在电脑前时，那个会话会无限挂住
- `仍然执行`：确认形同虚设，等于没开
- `拒绝执行`：发送方看到失败，会换人或重发 —— 唯一不会静默出错的选择

界面上选「一直等下去」会显示警告文字，说明这个后果。

**每个会话独立设置，并且可以「沿用全局设置」**

profile 里的是默认值，会话里可以覆盖。打开「沿用全局设置」时：
- 完全跟随 profile，profile 改了这里跟着变
- 你之前的设置不会丢，只是不生效

这个开关是必需的，否则某个会话被调过一次之后，就永远不再跟随默认值的变化，半年后没人说得清它为什么不一样。

### 修复

- **确认动作完全不生效：闸门读的是全局配置，不是会话配置**

  全局 `enabled=false`，会话覆盖 `enabled=true`，闸门按全局判定「不问」直接放行。用户明明开了确认，却被静默通过。

- **超时策略形同虚设：倒计时在客户端，而没人看着时客户端不在**

  seam 的 `askTimed` 由客户端倒计时决定何时超时。而群消息唤醒的 turn 通常没有任何浏览器在线 ——
  这正是这个功能最需要保护的场景。实测配置 300 秒的请求，5 分钟后仍在等待，会话无限挂住。

  改为 Host 侧自己兜底：`Promise.race([askTimed, deadline])`。超时判定不再依赖任何客户端。

- **`ask()` 要求问题带 `id`，缺了就整个被拒**

  错误码 `BAD_ANSWER` 被包在 message 里，表面只看到「没有许可（error）」，而弹框从未出现。
  这类问题只能靠记录 seam 的错误码定位，所以加了 `a2a-human-confirm-answer.json` 诊断。

- **答案结构是 `{answers:[{id, selected}]}`，不是 `{label}`**

  原代码读 `item.label`，永远读到空 —— 意味着**每一次通过都会被当成拒绝**。这个 bug 如果上线，
  功能会表现为「怎么点都没用」。

- **`askTimed` 不能传自己的 AbortSignal**

  `code: ASK_ABORTED`，每次立即失败。它自己管理超时（返回 `{pending:true}`），传 signal 被理解为调用方已放弃。

- **设置界面：改一个字段会覆盖其他字段**

  面板每次改动都发送整个 `effective` 快照。由于快照有延迟，从旧渲染发出的保存会把没改过的字段写回旧值。
  实测四个设置里三个回到默认，只有正在编辑的那个存活。前后端都改为只处理变动的字段。

### 会话级设置

新增 `%DSH_HOME%\a2a\session-settings.json`，按 sessionId 存覆盖值和 `inherit` 标志：
/profile 的 `groups.humanConfirm` 是默认值，这里存每个会话的例外。

### 测试

721 个（新增 47）：策略分支、问题文本、超时三策略、seam 失败路径、闸门只拦回复不拦只读、
会话级配置优先、Host 兜底超时、部分更新不覆盖。

### 已知限制

**确认卡片的显示取决于消息是怎么进来的。**

| 场景 | 卡片 | 保护 |
|---|---|---|
| 你在会话里要求助手回复某条群消息 | ✅ 正常显示，可以点「允许」或「拒绝」 | 真人确认 |
| 同事发来消息，助手自动响应 | ❌ 不显示 | 超时策略兜底（`onTimeout: deny` 会拒绝） |

原因（已定位到源码）：`dsh-client-ui-user-questions/lib/client.js:1762` 里

```js
const sessionId = ctx.sessions.scopeOf(owner);
if (sessionId === void 0) return next();      // 认不出这个 turn 属于哪个会话，就不应答
```

群消息唤醒的 turn，UI 客户端认不出它属于哪个会话，于是不应答，卡片不渲染。这是 DSH 的架构限制，不是本插件的
问题——用内置的 `ask_user_question` 做同样的事，结果一样。

**两种情况都有保护**，只是形式不同：人在时能点头，人不在时按超时策略处理。

### 实测证据

`onTimeout: deny`（超时会拒绝）配置下，点「允许」并提交后发帖成功：

```
18:08:51  askTimed 开始等待
18:09:56  {"pending":false,"answers":[{"id":"a2a-human-confirm","selected":["允许"]}]}
群里出现 #283 王五: 真人点击
```

deny 策略下仍然发帖，唯一解释是真人点了允许——不是超时放行。

## [0.1.9] — 2026-11-05

> 这一版几乎全部来自**真实点击**发现的问题：面板看起来对、后端看起来对，中间那条路是断的。
> 所有修复都有实测证据，见 `test-report/`。

### 新功能

- **回复记录「属于哪件事」，不只是「回给谁」**（`rootSeq`）

  `replyTo` 只指向被回复的那一条，所以回复链只能往回看一步。回答 #180 是回给李四，但 #180 可能是在回答 #179 ——
  晚来的人看不出 #181 和 #182 讨论的是同一件事。

  现在两个事实都保留：`replyTo`（回给谁，给被回复的人看）和 `rootSeq`（属于哪件事，给任何看线索的人看）。
  任意深度的回复都收敛到同一个根。

- **opencli adapter：用真人方式驱动 UI**

  `opencli dsh open / send / read` —— 打开实例、在输入框打字并发送、读屏幕上出现了什么。
  `read --contains "已加入"` 就是一个能真正证明「用户那条路走得通」的断言。

### 修复

- **面板每 2 秒轮询，但轮询回来的是死数据 —— 而它一直报「成功」**

  端点写成了 `value: { groups: publishGroups() }`。`publishGroups()` 返回的是整个快照对象
  （`{selfVersion, updatedAt, groups, cards, unreadTotal}`），所以 `value.groups` 是个对象而不是数组；
  客户端要求数组，拒绝后静默返回。

  **每次轮询都「成功」且什么都没写。** 页面永远停留在加载时注入的那份快照上。

  这就是「操作的时候看不到，刷新页面才看到」的真正原因，也是前面几轮修复全都「看起来没生效」的原因 ——
  修复是真的，但它们全部走这条通道，而通道在丢弃一切。

- **接手后其他会话仍显示在群里**

  接手会把旧会话的凭证作废（宿主重签），但本地账本行没有清理。于是每个旧会话继续认为自己还在群里。

  现在接手时删除同一个人的其他记录。**删而不是标记**：宿主已经不接受那枚凭证了，没有可恢复的东西。

- **接手按钮填的提示词后端不认**

  它让模型执行 `a2a_group_join`，但 `join` 只接受邀请令牌 —— 而换工作目录的人令牌早就用掉了。
  按钮指向一条后端会拒绝的路，而面板和工具各自看起来都正常。

  `join` 现在接受第二种同等强度的证明：成员自己的 `personId` + 手上的 `personKey`，按 `resolveMember`
  相同规则校验。光有 `personId` 不够，那是声明不是证据。

- **点两次按钮，输入框里两句话**

  `fillDraft` 是插入（在光标处），对 `@李四 ` 是对的，对一句完整指令是错的。完整指令改用 `replaceDraft`。

- **`a2a_groups` 显示「0 人」**

  `join` 没把宿主已经返回的 `memberCount` 存进账本。在第一次 `group_info` 之前，任何列表都显示 0 人，
  读起来像「群是空的」。

- **接手时重复发欢迎、重复通知群主**

  `announceJoin` 无条件执行。接手是「没走的人回来了」，不是新成员。

  另外：每次接手都看到欢迎消息，**不是新发的** —— 是首次入群时那条通知从未被 ack，每次读收件箱都会重现。
  接手时现在会把它标记为已读。

- **群列表把同一个群显示 4 次**

  面板按账本记录渲染，一个换过 3 次工作目录的人就有 4 条记录。现在按群去重，并新增 `knownSessionIds`
  让非最新会话仍能判断自己是否在群里。

- **`a2a_group_directory` 报 404 `unknown A2A agent`**

  它默认去问「本实例自己的 agent 名」。成员实例不托管任何群，所以问它必然失败。
  群目录在宿主上，而所有群调用本来就都走宿主。

  > 第一反应是去网关注册那个 agent。那会让症状消失并教出错误的结论 —— 成员 agent 的用途是让同事直接找你，
  > 群协作从不需要它。改的是代码，不是配置。

- **投递文案在教模型「必须回帖」**

  每次投递都以「Answer with a2a_group_post to the same group」结尾。配合 `replyTo` 那句「回复会唤醒对方」，
  两条规则闭成一个环：被 @ → 必须回 → 回复唤醒对方 → 对方又必须回。

  三人群里一条四行的测试广播产生了四条回复，其中一个人回了两次。

  真实协作里是否回复、什么时候回、回什么质量由接收方决定，发起者不能强制。文案现在只说明
  「你说给自己用户的话别人看不到」，不写命令。

  data: 'not_member'  // 字符串在这里

### 一个教训：fake 抛你期待的形态，就发现不了真实形态不一样

远程标记失效那个 bug，单测全绿了整整两轮。因为 fake 这样抛错：

```js
const error = new Error(code); error.code = code; throw error;
```

和本地调用一模一样。而真实的远程错误形状完全不同。

新的测试统一用**真实形态**：`code` 放 JSON-RPC 数字，`data` 放业务子码。

### 新增

- **加入页面**：一个 URL，打开后有一段可粘贴给 AI 助手的配置说明。

  它解决的是「装了插件、面板空白、不知道要配什么」这个死结 —— 配置知识从文档搬进了助手手里。

  设计上的四个决定：

  - **一次性 + 15 分钟有效**：页面带凭证，落在聊天记录里的 URL 不能长期有效
  - **先看 diff 后写**：让 AI 改配置文件和不安全请求长得一样，拒绝是对的直觉
  - **链接由浏览器算**：网关可能在路径前缀处挂载并剥掉前缀，宿主永远只看到 `/join`。
    `location.pathname` 有它，所以前端算而不是后端猜
  - **页面自己报场景**：是「加入协作群「甲群」」还是「加入协作模式」，四处标出，不让新人对着 YAML 发懵

  而它需要群 —— 全新宿主（0 个群）因此没有任何入口，是个自锁。

  接入和加群是两件事：**配置是先决条件，加群是之后可选的**。

### 修复

- **加入页面永远显示第一个群**
  `joinContext()` 不接受参数，所以给 A 群的邀请链接，打开后显示的是排序第一的群。

  这比空白页更糟：对方会把自己配置进**一个从没被邀请的群**，而他手里的邀请还没用掉。

  现在 token 带 `&g=群id`，群不存在就拒绝，不静默替换。

- **`--public-url` 是假的**：解析了、打印在启动日志里，但从没写进 config。参数看起来支持，实际什么也没做。

- **链接用了监听地址而非可访问地址**：宿主监听 `127.0.0.1:3095`，实际在 `https://gw.company.com`。

  四种来源按序：`server.publicUrl` > `X-Forwarded-*` > `Forwarded`(RFC 7239) > `Host`。
  配置优先于转发头 —— 代理可能既加了转发头又保留原 Host，只有人写下的那个不是猜的。

  **路径前缀无法自动判断**：宿主的 `/join` 被网关变成了什么，它看不见。这部分由浏览器补全。

- **`/__health` 不报告 origin**：运维没法判断「宿主以为的地址」和「实际访问的地址」是否一致，
  而这正是决定邀请链接能否在别人机器上打开的唯一问题。现在报了。

3. **三次行编辑让函数体、注释、声明错位**：局部看都对，整体是坏的。最后整块重写

## 实现备忘

这些不是变更，是**下次改这块代码前该知道的事**。

### 面板写入通道的四个坑

1. **`ctx.connection.rpc.handle()` 从插件自己的 fiber 调用会抛**
   `cannot get property "webServer" without inject` —— 上游 bug（#8414）。**必须用 `ctx.root`**。

2. **浏览器侧不是 `createWebConnectionRpc`**
   那个名字是内部的。模块真实导出是 `{ RpcId, apply, inject, installConnection, transportError }` ——
   它是插件，发布的是 `connection` 服务。调用方式：
   ```js
   ctx.connection.rpc.call(channel, endpoint, payload)
   ```
   与宿主的 `handle` 完全对称。

3. **`dsh.client.inject` 是模块表，不是服务列表**
   包里只能 `require` 在这里声明过的模块。只写 `slots` 时，`require('@dsh-client-connection')` 会抛，
   面板报「module 未能加载」—— 但其实模块从未被提供。

4. **裸 POST 会 405**
   传输层带的是 `ClientRequest` 信封（`{ type, rpcId, method, payload }`），不是裸 body。

### 为什么写操作在宿主执行

凭证不出宿主、不需要第二套鉴权、Connection 已做认证。

**面板带 personKey 的话，DOM 里能读到** —— 等于把每个群的凭证交给任何能读页面的人。

### 测试的两个盲区

- **断言返回值，不断言「不抛 ReferenceError」**：三个核心工具曾 100% 崩溃（缺 import），测试全绿。
- **断言渲染文本，不断言字段结构**：`from` 被降级成字符串，测试没发现。

### MCP 推送：协议支持，生态不消费

MCP 有 `notifications/message` 和 `notifications/resources/updated`，传输层也支持 SSE。**但没有任何主流
客户端把通知变成一轮对话** —— 通知到达的是客户端程序，不是模型。

实测三条路都不通：

| 机制 | 结果 |
|---|---|
| `instructions` | CodeBuddy **完全丢弃**（直接问它那句话在不在，答「没有」） |
| `prompts/list` | 只作为 slash command 暴露，要用户手动敲 `/` |
| `tools` | 进 `<available_deferred_tools>`，**只给名字**，无描述无 schema |

所以实际用法是**在提示词里明确要求模型去查**：

```bash
codebuddy -p "先调用 a2a_pending 看有没有协作群消息，有未读先处理。然后：<任务>"
```

要真正的推送，只能让宿主主动调客户端的非交互模式（`codebuddy -p`、`claude -p`、`opencode`），代价是每次
唤醒冷启动一个进程。**当前没做。**
