## [0.1.8] — 2026-11-05

> 这一版几乎全部来自**真实点击**发现的问题：面板看起来对、后端看起来对，中间那条路是断的。
> 所有修复都有实测证据，见 `test-report/`。

### 新功能

- **回复记录「属于哪件事」，不只是「回给谁」**（`rootSeq`）

  `replyTo` 只指向被回复的那一条，所以回复链只能往回看一步。回答 #180 是回给李四，但 #180 可能是在回答 #179 ——
  晚来的人看不出 #181 和 #182 讨论的是同一件事。

  现在两个事实都保留：`replyTo`（回给谁，给被回复的人看）和 `rootSeq`（属于哪件事，给任何看线索的人看）。
  任意深度的回复都收敛到同一个根。

- **opencli adapter：用真人方式驱动 UI**

  `opencli dsh open / send / read` —— 打开实例、在输入框打字并发送、读屏幕上出现了什么。
  `read --contains "已加入"` 就是一个能真正证明「用户那条路走得通」的断言。

### 修复

- **面板每 2 秒轮询，但轮询回来的是死数据 —— 而它一直报「成功」**

  端点写成了 `value: { groups: publishGroups() }`。`publishGroups()` 返回的是整个快照对象
  （`{selfVersion, updatedAt, groups, cards, unreadTotal}`），所以 `value.groups` 是个对象而不是数组；
  客户端要求数组，拒绝后静默返回。

  **每次轮询都「成功」且什么都没写。** 页面永远停留在加载时注入的那份快照上。

  这就是「操作的时候看不到，刷新页面才看到」的真正原因，也是前面几轮修复全都「看起来没生效」的原因 ——
  修复是真的，但它们全部走这条通道，而通道在丢弃一切。

- **接手后其他会话仍显示在群里**

  接手会把旧会话的凭证作废（宿主重签），但本地账本行没有清理。于是每个旧会话继续认为自己还在群里。

  现在接手时删除同一个人的其他记录。**删而不是标记**：宿主已经不接受那枚凭证了，没有可恢复的东西。

- **接手按钮填的提示词后端不认**

  它让模型执行 `a2a_group_join`，但 `join` 只接受邀请令牌 —— 而换工作目录的人令牌早就用掉了。
  按钮指向一条后端会拒绝的路，而面板和工具各自看起来都正常。

  `join` 现在接受第二种同等强度的证明：成员自己的 `personId` + 手上的 `personKey`，按 `resolveMember`
  相同规则校验。光有 `personId` 不够，那是声明不是证据。

- **点两次按钮，输入框里两句话**

  `fillDraft` 是插入（在光标处），对 `@李四 ` 是对的，对一句完整指令是错的。完整指令改用 `replaceDraft`。

- **`a2a_groups` 显示「0 人」**

  `join` 没把宿主已经返回的 `memberCount` 存进账本。在第一次 `group_info` 之前，任何列表都显示 0 人，
  读起来像「群是空的」。

- **接手时重复发欢迎、重复通知群主**

  `announceJoin` 无条件执行。接手是「没走的人回来了」，不是新成员。

  另外：每次接手都看到欢迎消息，**不是新发的** —— 是首次入群时那条通知从未被 ack，每次读收件箱都会重现。
  接手时现在会把它标记为已读。

- **群列表把同一个群显示 4 次**

  面板按账本记录渲染，一个换过 3 次工作目录的人就有 4 条记录。现在按群去重，并新增 `knownSessionIds`
  让非最新会话仍能判断自己是否在群里。

- **`a2a_group_directory` 报 404 `unknown A2A agent`**

  它默认去问「本实例自己的 agent 名」。成员实例不托管任何群，所以问它必然失败。
  群目录在宿主上，而所有群调用本来就都走宿主。

  > 第一反应是去网关注册那个 agent。那会让症状消失并教出错误的结论 —— 成员 agent 的用途是让同事直接找你，
  > 群协作从不需要它。改的是代码，不是配置。

- **投递文案在教模型「必须回帖」**

  每次投递都以「Answer with a2a_group_post to the same group」结尾。配合 `replyTo` 那句「回复会唤醒对方」，
  两条规则闭成一个环：被 @ → 必须回 → 回复唤醒对方 → 对方又必须回。

  三人群里一条四行的测试广播产生了四条回复，其中一个人回了两次。

  真实协作里是否回复、什么时候回、回什么质量由接收方决定，发起者不能强制。文案现在只说明
  「你说给自己用户的话别人看不到」，不写命令。

- **白名单 mapper 丢字段（第 6、7、8、9 次）**

  `rootSeq`、`knownSessionIds`、`lastSeq`、`memberCount` 先后被不同的 mapper 丢掉。每次表现都像不同的 bug，
  根因都是同一个：**宿主发布了，mapper 没复制，读出来是 `undefined`，而 `undefined` 读起来像「不适用」**。

  `feed-field-parity` 现在会在加字段时直接变红并指出漏了哪一层 —— 这次它先于任何人发现了 `group/read` 的遗漏。

### 文档

- 新增 `docs/OPENCLI-ADAPTER.md`：11 条实测踩坑，每条都附现象和修法
- `test/README.md` 增加「一·五、UI 相关改动必须用浏览器实操验证」，附四个「测试全绿但功能是坏的」案例

## [0.1.6] — 未发布

### 修复

- **`a2a_person_inbox` 的凭证选择不确定**

  它用 `identities.list({ sessionId })[0]` —— **第一行，不管那是哪个群**。一个同时在本地托管群和远程群的实例，
  收件箱会从「碰巧排第一」的那个成员身份去查。

  这个 bug 的表现是一次 **CI-only failure**：本地 566 个测试全绿，CI 上同一条测试返回 0 条消息。
  原因是账本返回行的顺序在不同运行时下不保证 —— 本地先返回了远程群，CI 先返回了本地群（本地收件箱是空的）。

  测试现在用一个只持有远程成员身份的独立会话，**明确**走远程路径。工具本身的行为没有改：
  它的选择仍然是「第一个」，这被记录下来了而不是被掩盖。

### 新增

- **可以退群了**（`a2a_group_leave`，第 27 个工具）

  之前`group/leave`只以 A2A skill 存在，而它的实现是 `store.leave(...)` —— **只对本地托管的群有意义**。
  对远程群（也就是普通成员用的场景）**没有任何退群手段**，宿主会一直保留一个无法发言的成员。

  正确的顺序只有一种：

  ```
  远程群：先带凭证请求宿主移除我 → 成功才删本地 → 失败则保留 + 标记 leavingAt
  本地群：store 就是权威，一次调用即完成
  ```

- **`docs/STATE.md`**：成员状态机。六种状态、转换图、哪些能收敛哪些不能，以及
  「为什么服务端跟随本地这个方向物理上做不到」的完整推理。

- **覆盖率门槛**（`scripts/coverage.mjs --check`），分两级：

  | 级别 | 行 | 分支 |
  |---|---|---|
  | 核心不变量（groups/bridge/invite/memberships/wire/server） | 85% | 75% |
  | 其余 | 80% | 60% |

  分级的理由：整体数字被 `tool-runtime.js`（27 个工具、每个 8-12 个分支）主导，
  追平全局 75% 分支意味着测试「tags 传字符串会怎样」这类几乎不保护任何东西的分支。
  真正需要分支覆盖的是持有不变量的模块——那里漏一个分支，就是一条规则没被守住。

### 修复

- **`a2a_send` 不校验 message**

  spec 里 `message` 是 required，但 handler 直接把 `args.message` 传给 bridge。
  模型漏传时会发出空消息，失败发生在对端而不是这里。现在用 `requireText` 兜底。

- **远程群的空闲标记从来没生效过**

  `reapStaleMembership` 检查 `error.code === 'not_member'`。这对**本地调用**是对的，
  但远程调用经过 `bridge.js` 包装后，`code` 是 JSON-RPC 数字 `-32004`，
  业务子码在 **`data`** 里。

  ```js
  code: -32004,       // 数字
  data: 'not_member'  // 字符串在这里
  ```

  所以两轮前加的「标记失效 + 成功清除」机制，**对本地群有效，对远程群完全没生效**——
  而成员访问的全是远程群。单元测试没抓到，因为 fake 抛的正是本地形态。

- **`a2a_groups` 对远程群显示 0 人**

  成员数只从 `safeList`（本机托管的群）取，远程群拿到 undefined 就回退成 0。
  而账本里缓存着正确的数字，从没被读过。

- **`group/read` 远程分支把 `from` 对象原样透传**

  schema 要求 `from` 是字符串，宿主产出的是 `{ personId, displayName }`。
  本地分支会先降级，远程分支不会——所以**同一个工具，群在哪决定了它能不能用**。

  这是从真实双实例测试里发现的，报告精确到了行号。

- **`group/join` 不幂等**

  重复调用会产生**两个独立身份**，而凭证只在入群响应里发一次，第二个身份永远无人使用。

- **缓存名单没有失效上限**

  `rosterCachedAt` 一直存在，但从未和当前时间比较过。现在超过 10 分钟就标记，面板提示「来自缓存」。

### 一个教训：fake 抛你期待的形态，就发现不了真实形态不一样

远程标记失效那个 bug，单测全绿了整整两轮。因为 fake 这样抛错：

```js
const error = new Error(code); error.code = code; throw error;
```

和本地调用一模一样。而真实的远程错误形状完全不同。

新的测试统一用**真实形态**：`code` 放 JSON-RPC 数字，`data` 放业务子码。

## [0.1.5] — 2026-11-04

### 新增

- **加入页面**：一个 URL，打开后有一段可粘贴给 AI 助手的配置说明。

  它解决的是「装了插件、面板空白、不知道要配什么」这个死结 —— 配置知识从文档搬进了助手手里。

  设计上的四个决定：

  - **一次性 + 15 分钟有效**：页面带凭证，落在聊天记录里的 URL 不能长期有效
  - **先看 diff 后写**：让 AI 改配置文件和不安全请求长得一样，拒绝是对的直觉
  - **链接由浏览器算**：网关可能在路径前缀处挂载并剥掉前缀，宿主永远只看到 `/join`。
    `location.pathname` 有它，所以前端算而不是后端猜
  - **页面自己报场景**：是「加入协作群「甲群」」还是「加入协作模式」，四处标出，不让新人对着 YAML 发懵

- **无群也能接入**：启动时打印 configure-only 链接。之前只有 `group/invite` 能生成链接，
  而它需要群 —— 全新宿主（0 个群）因此没有任何入口，是个自锁。

  接入和加群是两件事：**配置是先决条件，加群是之后可选的**。

### 修复

- **加入页面永远显示第一个群**
  `joinContext()` 不接受参数，所以给 A 群的邀请链接，打开后显示的是排序第一的群。

  这比空白页更糟：对方会把自己配置进**一个从没被邀请的群**，而他手里的邀请还没用掉。

  现在 token 带 `&g=群id`，群不存在就拒绝，不静默替换。

- **`--public-url` 是假的**：解析了、打印在启动日志里，但从没写进 config。参数看起来支持，实际什么也没做。

- **链接用了监听地址而非可访问地址**：宿主监听 `127.0.0.1:3095`，实际在 `https://gw.company.com`。

  四种来源按序：`server.publicUrl` > `X-Forwarded-*` > `Forwarded`(RFC 7239) > `Host`。
  配置优先于转发头 —— 代理可能既加了转发头又保留原 Host，只有人写下的那个不是猜的。

  **路径前缀无法自动判断**：宿主的 `/join` 被网关变成了什么，它看不见。这部分由浏览器补全。

- **`/__health` 不报告 origin**：运维没法判断「宿主以为的地址」和「实际访问的地址」是否一致，
  而这正是决定邀请链接能否在别人机器上打开的唯一问题。现在报了。

### 三个只有跑浏览器才会发现的 bug

1. **DOM clobbering**：函数叫 `shareLink`，而 `id="shareLink"` 让全局变量指向元素，调用报 `is not a function`
2. **模板字符串吃掉反斜杠**：正则字面量输出后变成注释，模式失效且无报错
3. **三次行编辑让函数体、注释、声明错位**：局部看都对，整体是坏的。最后整块重写

### 测试

473 个测试，其中 22 个是本轮新增：令牌一次性/过期/未知、指令完整性、两种模式、
HTML 转义、前缀推导（含尾部斜杠与形似路由的路径段）。

## [0.1.4] — 2026-11-04

### 修复

- **远程群的保存会在成功之后报失败**
  `setPanelProfile` 把 `const saved` 声明在 `if (record.local === true)` 分支内，而 `return` 在分支外读
  `saved?.changed`。结果：本地群正常，**远程群抛 `saved is not defined` —— 而写入其实已经到达宿主并成功了**。

  用户看到「保存失败」，数据却是对的。这是最误导人的失败形态：会让人重复保存，或来报一个「功能坏了」的
  假 bug。

  新增 3 个测试守**声明顺序**（不执行 handler 也能看出问题），并验证过还原成 bug 版本时会立刻失败。

- **面板写入失败不留痕迹**
  之前只返回 `write_failed`，`err.log` 全空。用户报告无法复现，只能写探针脚本才查出来。
  现在 catch 里打真实原因：`[a2a-panel] write failed for g-xxx: <原因>`。

### 新增

- **工具面能设置个人介绍了**
  `persons.headline` 一直是完整存在的：能存、能在面板改、名片会显示。但**没有工具能写它** —— 模型被要求
  「更新我的介绍」时只能说「请用面板」。

  `a2a_group_role` 加了 `headline` 参数。放在同一个工具而不是新开 `a2a_person_profile`，因为两者都是从
  「我是谁」这一行出发的自述，另开一个单字段工具只会让模型纠结该用哪个。

  互不干扰：只传 `about` 不会清掉 `headline`，反之亦然；空字符串才清空。这是最容易写错的地方 ——
  调用方自然只会传「正在改的那个」。

  **这个缺口是在写 RUNBOOK 时发现的**：文档里写了用哪个工具设介绍，核对工具名时才发现它不存在。

### 文档

- **安装是两步，第二步是静默的**
  `dsh plugin --profile web add dsh-a2a-groups@latest` 只把包装进 `node_modules`，**不加入
  `dsh.profile.bundles`**。漏了这步重启后 UI 里什么都没有，`err.log` 也不报错 —— 用户没有任何线索可搜。

  `dsh plugin` 只是 pnpm 的转发器，负责装包；是否挂载是另一件事。所以这写在 README 的编号步骤里，
  不是排错章节。

- **`RUNBOOK.md` 重写为纯操作手册**：只留「怎么跑起来、怎么用」，历史与踩坑移到这里。新同事不需要知道我们
  修过什么 bug，也不需要读 27 个编号的 bug 才能找到启动命令。

## [0.1.2] — 2026-11-04

### 变更

- **包名 `dsh-a2a` → `dsh-a2a-groups`**
  `dsh-a2a` 在 npm 上已被占用。改名后仓库、包名、插件 id 统一。

  **改名要动四处，改一处就坏，且三处无报错**：

  | # | 位置 | 不改的后果 |
  |---|---|---|
  | 1 | `package.json` 的 `name` | 包身份不对 |
  | 2 | 包内 `cordis.patch.yml` 的 `name:` | `cannot resolve profile bundle` |
  | 3 | profile 的 `dsh.profile.bundles` | 不挂载，**UI 无按钮且 err.log 干净** |
  | 4 | `client.js` 的 `__ModuleLoader__.load({ id })` | `loaded without registering "<新名>"` |

  第 4 处最阴：模块**加载是成功的**，只是注册到旧名下，加载器认为这个包没提供它要的东西。

  `bundle registers under the package name` 这个测试已改为从 `package.json` 读期望值，并比对
  `cordis.patch.yml`。写死字面量的版本改名后只会报「期望 dsh-a2a」，读起来像测试过时而非代码错了。

### 新增

  `DEPLOY.md`（部署）、`MCP.md`（MCP 接入）、`RUNBOOK.md`（运行手册）。

### 安全

  `sk-dev-niukl-2026`、`agent-groups-host-token-2026`、`dsh-a2a-dev-token-*` 及其 sha256。
  虽然只是本地 dev 环境的值，但公开仓库是永久的，而这些值暴露了内部网络的机器名、端口分配、密钥命名。

  现在全部从环境变量读，缺省值用明显是假的值（`dev-caller-key-not-a-secret`），脚本仍能对本地 mock 运行。

  > **注意**：仓库里的 `scripts/aisix-dev/resources.yaml` 是**模板**。网关容器实际跑的是
  > `~/aisix-dev/data/resources.yaml`（挂载到 `/etc/aisix`）。改模板不影响运行中的网关 —— 反过来，
  > 网关突然对所有请求返 401 时，先查容器里那份。

- **面板不再携带消息正文**：快照注入到页面 HTML，含正文会随缓存、截图、代理泄露。

## [0.1.1] — 2026-11-04

### 新增

- **`a2a_pending`**：一次调用回答「有什么在等我」。返回未读群消息 + 一对一邀请，一对一在前（邀请会阻塞进度）。

  设计成可以频繁调用：不抛异常、不编造未读数（远程群未读取时报「未知」而非 0）。

  配套重写了 MCP 的 `instructions`，教模型**什么时候该查**。但**实测无效** —— 见下方「已知限制」。

- **个人介绍（`headline`）与群内介绍（`about`）分离**
  两个字段作用域不同：`about` 是「我在这个群负责什么」，换群就变；`headline` 是「我是谁」，跟着人去所有群。

  新增 `person/profile` skill（原来只有 `group/role`，管不了跨群属性）。

  同时给 `a2a_group_role` 加了 `headline` 参数 —— 在这之前，**工具面没有设置个人介绍的入口**，模型不能改，
  只能通过面板 UI。两个字段走同一个工具是因为都是从「我是谁」这一行出发的自述，另开一个只有一个字段的工具
  只会让模型纠结该用哪个。

  互不干扰：只传 `about` 不会清掉 `headline`，反之亦然；空字符串才清空。

- **邀请结果三态反馈**：「正在发送」/「已邀请，对方在线」/「已邀请，对方当前离线」/「发送失败：原因」。

  「已发出」和「对方现在能看到」是两个不同的承诺，合并成一个勾会让人在对方没立刻回复时以为功能坏了。

- 发送时禁用列表：每次邀请签发**一次性链接**，双击会产生两个有效链接而只有一个会被用掉。

### 修复

- **MCP 建的群邀请不了任何人**
  `a2a_group_create` 支持在远程宿主上建群（这是常态），但 `a2a_group_invite` 强制 `local === true`。

  **只有 MCP 场景必然暴露** —— MCP 客户端没有任何本地托管的群，所有操作都走远程。单测覆盖的是本地场景。

  修复：加 bridge 分支，由持有令牌表的宿主签发。

- **`group/read` 把 `from` 降级成了字符串**
  ```js
  from: entry.from.displayName,   // ← 丢掉了字段名
  personId: entry.from.personId,  // ← 提到了平级
  ```
  但 `publicEntry` 约定是 `from: { personId, displayName }`。所有读 `from.displayName` 的消费者拿到
  `undefined`。

  测试断言了 `from.personId` 和面板文本，**没断言结构**，所以一直绿的。

  这只有跑真实的四进程走查才会暴露。

- **相同值保存也广播**
  角色保存无条件写系统条目，导致「X 更新了本群角色」刷屏。成员观察到间隔从两小时缩到 100 秒，合理怀疑
  「有客户端在循环调用」。

  修复：比较前后值（tags 两边排序后比较），无变化返回 `changed: false`，**且不更新 `profileUpdatedAt`**
  —— 那个字段的含义是「最后修改时间」，空存一次就刷新等于说谎。

- **入群通知从未发送**
  `person/send` 支持 `join-notice` 和 `welcome` 两种类型，但代码里**从来没有人调用它们**。邀请是单向的：
  群主推链接，然后什么都不知道。

  现在双向发，且：欢迎语不能由被欢迎者签名（`sendPersonMessage` 拒绝自发消息）；两条消息都不带邀请令牌
  （否则令牌进群主收件箱，正是转发截图的来源）；通知失败不影响入群（成员已经落盘了）。

## 实现备忘

这些不是变更，是**下次改这块代码前该知道的事**。

### 面板写入通道的四个坑

1. **`ctx.connection.rpc.handle()` 从插件自己的 fiber 调用会抛**
   `cannot get property "webServer" without inject` —— 上游 bug（#8414）。**必须用 `ctx.root`**。

2. **浏览器侧不是 `createWebConnectionRpc`**
   那个名字是内部的。模块真实导出是 `{ RpcId, apply, inject, installConnection, transportError }` ——
   它是插件，发布的是 `connection` 服务。调用方式：
   ```js
   ctx.connection.rpc.call(channel, endpoint, payload)
   ```
   与宿主的 `handle` 完全对称。

3. **`dsh.client.inject` 是模块表，不是服务列表**
   包里只能 `require` 在这里声明过的模块。只写 `slots` 时，`require('@dsh-client-connection')` 会抛，
   面板报「module 未能加载」—— 但其实模块从未被提供。

4. **裸 POST 会 405**
   传输层带的是 `ClientRequest` 信封（`{ type, rpcId, method, payload }`），不是裸 body。

### 为什么写操作在宿主执行

凭证不出宿主、不需要第二套鉴权、Connection 已做认证。

**面板带 personKey 的话，DOM 里能读到** —— 等于把每个群的凭证交给任何能读页面的人。

### 测试的两个盲区

- **断言返回值，不断言「不抛 ReferenceError」**：三个核心工具曾 100% 崩溃（缺 import），测试全绿。
- **断言渲染文本，不断言字段结构**：`from` 被降级成字符串，测试没发现。

### MCP 推送：协议支持，生态不消费

MCP 有 `notifications/message` 和 `notifications/resources/updated`，传输层也支持 SSE。**但没有任何主流
客户端把通知变成一轮对话** —— 通知到达的是客户端程序，不是模型。

实测三条路都不通：

| 机制 | 结果 |
|---|---|
| `instructions` | CodeBuddy **完全丢弃**（直接问它那句话在不在，答「没有」） |
| `prompts/list` | 只作为 slash command 暴露，要用户手动敲 `/` |
| `tools` | 进 `<available_deferred_tools>`，**只给名字**，无描述无 schema |

所以实际用法是**在提示词里明确要求模型去查**：

```bash
codebuddy -p "先调用 a2a_pending 看有没有协作群消息，有未读先处理。然后：<任务>"
```

要真正的推送，只能让宿主主动调客户端的非交互模式（`codebuddy -p`、`claude -p`、`opencode`），代价是每次
唤醒冷启动一个进程。**当前没做。**
