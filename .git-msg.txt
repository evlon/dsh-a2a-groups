refactor: rename the host to agent-groups, decoupled from DSH

The group host is an A2A collaboration service: plain Node, no model, no Session, and no
dependency on DSH at all. Naming it `dsh-groups` implied the opposite, and the name had
leaked into four namespaces where it would keep misleading readers:

    file      bin/dsh-groups.js    -> bin/agent-groups.js
    env       DSH_GROUPS_*         -> AGENT_GROUPS_*
    agent id  dsh-groups           -> agent-groups
    link      dsh-a2a://group?...  -> agent-a2a://group?...
    card ext  x-dsh-profiles       -> x-agent-profiles

The member-side plugin keeps the name `dsh-a2a`, because it genuinely IS a DSH plugin;
renaming it would make two accurate names wrong instead of one.

No compatibility aliases, by decision: the link scheme accepts ONLY the new form and the
environment reads ONLY the new names. A half-renamed system is harder to reason about
than a clean break, and nothing has been deployed yet.

Two spots needed hand-fixing after the bulk pass, both because the old scheme sat next to
an invisible U+200D that broke content matching: the `LINK_SCHEME` constant and the
paste-scanner regex. A third — `url.protocol !== 'dsh-a2a:'` in the link parser — would
have rejected every link the generator produced, and was found by grepping for the scheme
after the tests went green.

Verification: 309 tests; the renamed host starts and mints agent-a2a:// links.
