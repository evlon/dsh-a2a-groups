docs: state the MCP polling limit honestly, and fix every stale tool count

Two corrections, both the kind that erode trust in a doc once a reader checks them.

THE POLLING STORY WAS WRONG IN A SUBTLE WAY

The old text said "MCP 的 Server 不能主动向 Client 发消息" — that is false. The protocol carries
`notifications/message` and `notifications/resources/updated`, and the transport supports SSE. What is true is
that no mainstream client turns a notification into a model turn.

The difference matters. "Impossible" tells a reader not to look; "supported but unused by clients" tells them
where the actual obstacle is. So MCP.md now says the second thing, with what was measured:

    instructions        CodeBuddy drops it entirely — asked whether a sentence from it was present, "没有"
    prompts/list        exposed as a slash command only; never enters context automatically
    tools               land in <available_deferred_tools> with the NAME only, no description, no schema

And the practical advice follows from that: ask for the poll in the prompt, because nothing else will.

    codebuddy -p "先调用 a2a_pending 看有没有协作群消息，有未读先处理。然后：<任务>"

The alternative — having the host invoke the client's non-interactive mode when a message arrives — is
described and explicitly marked as not built, with its costs: a cold process per wake, and per-client
adaptation.

STALE COUNTS, FIXED EVERYWHERE

Seven places said 19 tools. The real number is 26. A reader who checks `tools/list` and finds a mismatch stops
believing the rest of the page, so the count is now taken from the spec by `scripts/sync-tool-count.mjs` rather
than typed.

The first run of that script reported 23 — its regex assumed four spaces of indentation where the file uses
six. Caught by comparing against `TOOL_SPECS.length`, which is exactly why the script counts instead of me.

Also completed the tool table in MCP.md: it was missing six entries, including `a2a_pending`, the one tool the
new instructions tell a model to call first.

Verified: 427 tests, MCP probe OK, and `docs` now references all 26 tools with no stale count anywhere.
