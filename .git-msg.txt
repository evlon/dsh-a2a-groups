feat(ui): edit my group role in place, without opening a conversation

The panel is the interface for a collaboration group. Asking somebody to press 「编辑介绍」, watch an
instruction appear in a composer, and then press Enter — in order to change a label on a roster — was the
wrong shape: they are looking at people, not talking to an assistant.

My row now expands into two fields and a save button. The write goes straight to the Host over the
Connection channel and the value changes for every member.

Verified from the UI, read back from the Host's own file:

    before  张工: '整体进度与验收' [产品]
    after   张工: 'UI真实保存测试' [前端,测试]

TWO BUGS FOUND ON THE WAY, BOTH PREVIOUSLY INVISIBLE

1. **Membership base URLs were missing the agent name.** The invite link carries `gw` (gateway root) and
   `agent` (the entry under it) as separate facts, correctly — but only `gw` was stored, so every later
   call posted to `/a2a`, which the gateway answers 404 for. Measured:

       POST /a2a                    -> 404
       POST /a2a/agent-group-host   -> 200

   This went unnoticed because a locally hosted group takes the `local` branch and never touches the
   network, and because `group/join` resolves the card first and so succeeded while every subsequent call
   did not. That is the most confusing shape a networking bug takes.

2. **`parsed.baseUrl` is the direct endpoint, not the gateway base.** `parseInviteLink` returns
   `gatewayBase` and `agent` separately; the compose step has to read those.

FALLBACK KEPT

If the write channel is unavailable the button still fills the composer. A host without Connection should
lose convenience, not the ability to edit — and the panel says which path it took rather than silently
doing the other thing.

Also recorded: `opencli browser fill` is what works for driving a controlled React input. `dispatchEvent`
with a native setter throws `Illegal invocation` across realms, and `type` errored — worth knowing before the
next UI verification spends ten minutes on it.
