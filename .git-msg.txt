refactor: split the tool surface into specs, runtime, and a thin DSH adapter

`tools.js` was 1676 lines holding three concerns at once: the protocol description
(models read it), the business logic, and the DSH registration call. Adding an MCP host
would have meant either duplicating that logic or drifting from it.

    tool-specs.js     name / description / parameters / output / render   pure data
    tool-runtime.js   the 19 execute bodies, taking { sessionId }         pure logic
    tools.js          specs + runtime -> ctx.tools.register               93 lines

The seam turned out to be one function. `senderOf(exec)` read `exec.agent.id` — a DSH
detail buried in the middle of the bodies. It now reads `{ sessionId }`, which each
adapter supplies its own way, so not one tool body knows which host it is running in.

That single mapping is why the split is worth doing rather than just tidy: a DSH Session
id and an MCP connection id are the same fact to these tools, and the group mutators need
exactly one such fact because a membership belongs to one conversation.

Verified: 309 tests, unchanged behaviour. tools.js 1676 -> 93 lines. The three helpers
other modules import (joinUrl, coded, parseInviteLink) are lifted verbatim rather than
moved, so no call site churned.
