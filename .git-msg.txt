fix: the host was writing its own address onto every member

Found by running the real flow with two instances rather than by reading the code.

`group/join` executes INSIDE the host process, so `ownEndpointFromConfig(config)` there names the
host. Every member who joined was therefore recorded at the host's own address:

    张工  http://gw/a2a/agent-group-host     (should be agent-person-dev1)
    李四  http://gw/a2a/agent-group-host     (should be agent-person-dev2)

Two different people, one address, and it pointed at the wrong process even for the owner — a card
would have said "reach them directly here" and dialled the group host.

WHY THE PREVIOUS COMMIT GOT IT WRONG

It assumed `join` ran on the member's machine. It does not: `group/join` is a host skill, and the
member-side work happens in the `a2a_group_join` TOOL, which runs on the member's machine and does
know its own configuration. The two are different processes with different configs, and the field
was filled from the wrong one.

WHAT CHANGED

- the host no longer composes a joiner's address at all; it takes only what the caller supplies
- the member-side tool sends its own, composed from ITS config, because that process knows
- `create` still composes one, because there the caller IS the host — same field, two processes,
  and the asymmetry is the point

A member with no gateway name sends nothing and stays empty. Empty now means "no address known"
instead of "here is a plausible lie".

Verified on two live instances: 张工 gets the host address, 李四 gets agent-person-dev2, and 王五 —
who sent none — stays empty. 403 tests unchanged.

ALSO FOUND (not fixed, recorded for the MVP decision)

A raw A2A call to a member instance returns an empty result: its tools need a Session, and only a
Session turn has one. That is correct behaviour, not a bug — but it means a colleague cannot be
driven by an outside HTTP caller, only through their own conversation. Worth knowing before anyone
plans on a gateway-level "just call that person" feature.
