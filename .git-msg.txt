feat(mcp): one call that answers "is anything waiting for me?"

MCP cannot push to a model. Notifications reach the CLIENT PROGRAM, and no mainstream client turns one into
a turn, so an agent using this server is never woken by a colleague. If it does not ask, it never learns — the
protocol has no path around that.

Asking needs one place to ask. Before this there were three overlapping answers and no entry point:
`a2a_person_inbox` covers one-to-one messages, `a2a_group_read` needs a group id the caller may not have, and
nothing computed an unread count at all. A model told "check your groups" had to guess.

`a2a_pending` returns, in one call:

    direct messages   unconfirmed only — an invitation blocks progress
    groups            name and unread count, computed the same way the panel does
    nothing           said plainly, so a poll that finds nothing is cheap and unambiguous

Designed to be called at the start of every turn, so it cannot throw when nothing is joined and never invents
an unread count for a remote group whose head it has not read — an unknown reported as zero would hide new
messages.

THE INSTRUCTIONS WERE REWRITTEN TO TEACH THE POLL

The old preamble described browsing and posting and never said "check for messages". A tool nobody is told to
call is a tool that does not exist. The new one states the WHEN (start of a turn), the WHY (this server cannot
reach you), the consequence of skipping it, and what to do with an empty answer.

MEASURED, AND IT DOES NOT WORK YET

CodeBuddy drops `instructions` entirely — asked directly whether a sentence from it was present, the answer was
"没有". It also puts MCP tools in a deferred list where only the NAME is visible:

    mcp__agent-groups__a2a_pending      (no description, no schema)

so a model would have to `ToolSearch` before calling anything. That is a client-side decision this server
cannot influence, and it means the poll has to be asked for by the user until a client honours instructions.

Verified: 427 tests, 26 tools aligned, and a direct `tools/call` returns
`{"total":0,"summary":"Nothing waiting."}`.
