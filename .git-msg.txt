fix: the directory renderer referenced a deleted variable, and point the gateway at the new name

Two defects that only appear once MCP talks to a real host:

- `a2a_group_directory`'s renderer still interpolated `${policy}` after join policy was
  removed from the directory row. Rendering threw "policy is not defined" — a code path
  the DSH tests never hit because they assert on the tool's VALUE, not its rendered text.
  The line also still promised a group password. Both fixed.

- `resources.yaml` registered `dsh-groups`, so a call for `agent-groups` came back
  "unknown A2A agent". Renaming the code without the gateway leaves the two halves
  disagreeing, which is the exact failure a half-done rename produces. Agent name, ACL
  entry and secret are now consistent.

Verified end to end: an MCP client over stdio → gateway → host → 29 real groups listed
with names, topics and counts. That is the whole chain the MCP server exists for.

docs/MCP.md documents the wiring for Claude Code, CodeBuddy and Cursor, states that
MCP has no UI by protocol, and notes the one real behavioural difference: MCP cannot
push, so a client reads with a2a_group_read instead of receiving.
