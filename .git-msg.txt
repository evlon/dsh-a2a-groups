docs: product and architecture docs, plus the gaps in the existing five

Two documents were missing, and four claims in the existing ones were wrong. Both halves matter — a wrong
number in a doc costs a reader's trust in the rest of the page, so this pass verified rather than asserted.

NEW

`docs/PRODUCT.md` — what this is for, not how it works. Three concrete scenarios (adding a colleague mid-
project, knowing who to ask, letting the assistant find people), the four product boundaries with the reason
for each (no auto-dispatch, no persistent DMs, no admin reading content, no group password), and a comparison
against using a group chat. The boundaries matter most: each one is a decision that a plausible "obvious"
feature was deliberately not built.

`docs/ARCHITECTURE.md` — the system as built. Directory boundary with the one-line test for where a file
belongs, the core modules with their real sizes, the two data flows (group messages arrive by outbound SSE;
direct messages by poll-and-ack), the identity model, and the panel's write channel.

CORRECTED — each one measured, not estimated

1. **"Only 3 `ctx` references outside `lib/dsh/`"** → there are **2**, both optional injections in
   `server.js`. Found by running the grep the doc itself recommends; the number in the text had been guessed.
2. **Skill count** said 19 `group/*` + 4 `person/*`; the real split is **18 + 4 = 22**.
3. **Tool count** appeared as 19 in seven places; it is **26**. Earlier commits fixed the docs but this
   verified nothing was left.
4. **`CONTRACT.md` had no entry for four modules that exist** — `endpoint.js`, `colleague-cards.js`,
   `person/profile`, `announceJoin` — plus the two behaviour changes (`setProfile` announcing only real
   changes, and `group/read` returning `from` as an object). A contract that omits them invites somebody to
   re-implement them.

`CONTRACT.md` also gained the reasoning behind the ones that were bugs, because the *reason* is what stops a
future edit from reintroducing them: the host must not compute its own endpoint for a member, an announcement
cannot be signed by its own recipient, and the invite token must not travel in a notice.

ADDED

`DEPLOY.md` §六之二 — MCP deployment. Server-side needs no change at all (same gateway, same path), which is
the point worth stating; and `AGENT_GROUPS_TOKEN` means the gateway key here, not the host token — the two
share a name and nothing else, which is the likeliest misconfiguration.

Verified: every module line count in ARCHITECTURE.md matches the file; every internal doc link resolves; 427
tests, MCP probe OK, standalone probe OK.
