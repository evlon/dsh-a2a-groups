refactor!: two gateway namespaces — group-host for the host, person-* for people

The gateway named a person with the word "group". Reading a 403 or a timeout in the logs, there was
no way to tell whether an address belonged to a group entry or to somebody's machine.

    agent-group-host       the host: ONE entry, every group
    agent-person-<who>     a person's DSH: ONE entry per machine

WHY ONLY ONE OF THEM CAN SHARE AN ENTRY

A group is DATA. Every group lives in one host's `groups.json`, and a request names the group in the
payload (`data.groupId`), so one URL path serves all of them — adding a group never touches the
gateway. That is why the host can carry every group behind one name.

A person is a PROCESS on their own machine. The gateway forwards a given path to exactly one
address, so two people behind one entry would leave one of their DSH instances permanently
unreachable. One entry per person is not a design preference; it is the only thing that works.

ALSO FIXED: the member ACL never admitted members

`allowed_agents` listed `agent-groups`, `agent-group*`, `group-*` — but a member instance registers
as `dsh-group`, which matched none of them. A member could join a group and then get 403 on every
subsequent call. The earlier commit on this branch added `dsh-group*` as a patch; that patch is
removed here, because a wrong name that still works is a wrong name that never gets fixed.

The namespace is now `agent-group-host`, `agent-group*`, `group-*`, `agent-person-*`.

Docs: DEPLOY gains a section on the two namespaces, including the table of why one is shareable and
the other is not — that asymmetry is the thing that will confuse the next reader. The rename itself
touched six lines of prose and left every `/opt/agent-groups`, `bin/agent-groups.js` and
`useradd agent-groups` alone: those are paths, not gateway names, and a blind replace would have
broken every command in the deployment guide.

Verified: 403 tests unchanged, MCP probe OK, standalone probe OK, all three gateway entries answer
200, and end to end through the gateway — create, invite, join, post, read — with the composed
endpoint now resolving to `agent-group-host` rather than the old name.
